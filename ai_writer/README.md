# ✍️ AI ライティングツール（個人用）

Python + Streamlit + Gemini API で作った、文章まわりの作業をまとめた個人用ツールです。
データベースもログインもありません。履歴はこの PC の中だけに保存されます。

## 入っているツール

| ツール | できること |
| --- | --- |
| 📝 ブログ記事作成 | テーマから構成案を作り、その構成で本文を執筆 |
| 🖊️ note記事作成 | 素材メモから note の語り口で執筆。タイトル案・ハッシュタグ・有料エリアの提案つき |
| 📧 メール返信作成 | 受信メールと要点から、そのまま送れる返信文を作成 |
| 📱 SNS投稿文 | X / Instagram / LinkedIn など、媒体の作法に合わせた投稿案 |
| 💡 タイトル・コピー | 切り口を変えたタイトル・キャッチコピーをまとめて出す |
| 📄 文章要約 | 箇条書き・議事録形式など、目的に合わせた要約 |
| 🔍 校正・推敲 | 誤字脱字や敬語を直し、修正理由も一覧で提示 |
| 🔄 リライト・言い換え | トーン・長さ・読者に合わせて書き直す |
| 🌐 翻訳 | 12言語対応。用語集の指定や訳の解説つき |
| 🧠 アイデア出し | 企画・ネタを切り口を変えて複数提案 |
| 💬 AIチャット | 編集者・厳しい読者などの役割を指定して壁打ち |
| 🖼️ サムネイル作成 | note / ブログ / X / Instagram / YouTube など媒体ごとの比率で画像を生成 |
| 🗂️ 履歴 | 過去の生成結果を検索・再利用・1件ずつ削除（元に戻すつき）|

## 準備

### 1. APIキーを取得する

[Google AI Studio](https://aistudio.google.com/apikey) で Gemini の APIキーを発行します（無料枠あり）。

### 2. 依存パッケージを入れる

```bash
python3 -m venv .venv
.venv/bin/pip install -r ai_writer/requirements.txt
```

### 3. APIキーを設定する

```bash
cp ai_writer/.env.example ai_writer/.env
# .env を開いて GEMINI_API_KEY= の右にキーを貼り付ける
```

`.env` を作らずに、起動後サイドバーへ直接キーを貼り付けても使えます（その場合はブラウザを閉じるまで有効）。

## 起動

プロジェクトのルート（このリポジトリの一番上）で実行します。

```bash
.venv/bin/streamlit run ai_writer/app.py
```

ブラウザで http://localhost:8501 が開きます。止めるときはターミナルで `Ctrl + C`。

## SEOを意識した記事を書く

ブログ記事作成の「SEOを意識して書く」をオンにすると、システムプロンプトに SEO 用の層が上乗せされます。

指定できるもの:

- **メインキーワード** — 検索窓に実際に打ち込まれる言葉
- **検索した人が求めていること** — 情報収集 / 手順 / 比較検討 / 購入直前 / トラブル解決。これで記事の骨格が変わります
- **自分だけが書ける材料（一次情報）** — 実体験・実測値・具体的な事例。ここが埋まっているほどありきたりでなくなります
- **一緒に出力するもの** — タイトル案（32字以内）/ メタディスクリプション / 結論の先出し / よくある質問（FAQ）/ 内部リンク案

方針として、キーワードの詰め込みはさせていません。指示しているのは次の点です。

- 検索意図に対する結論を冒頭で先に出す
- 見出しは、検索する人が実際に打ち込む言葉で書く
- 各見出しの直下2〜3文で、その見出しの問いに先に答える
- 「〜が大切です」のような、読んでも行動が変わらない一般論を書かない
- 根拠のない数値や出典を捏造しない

なお SEO モードのとき、文字数の指定は**本文だけ**に適用されます（タイトル案やFAQは別枠）。

### note記事の「検索からの流入も意識する」

note は Google 検索と note 内（検索・おすすめ・ハッシュタグ）の両方から読まれるので、指示の中身を変えています。

- **冒頭2〜3行**を、記事一覧やSNSで切り取られても内容が伝わる文にする（note は冒頭が一覧に出ます）
- 検索した人が知りたい答えを、**記事の前半で出し惜しみせずに**書く
- 見出しは検索語に寄せつつ、**note の記事として不自然にならない**表現にする
- 体験を語る部分は、抽象的な感想でなく**そのとき何が起きて何をしたか**を具体的に書く

一緒に出力できるもの: **記事の紹介文（noteの「記事の設定」に入れる100字）** / 冒頭の掴み3案 / 結論の先出し / FAQ。
SEO をオンにすると、タイトル案とハッシュタグ案の指示も変わります（ハッシュタグは大きめのタグ2〜3個＋具体的な小さめのタグ3〜5個の組み合わせ）。

note では検索対策より、**「素材メモ」に書いた実体験の具体性**のほうが効きます。

## プロンプトを自分で書き換える

出力の質を変えたいときは、3か所のどれかを直します。

| 変えたいこと | 場所 |
| --- | --- |
| 全ツール共通の作法 | `core/prompts.py` の `BASE_SYSTEM` |
| そのツールの人格・専門性 | `tools/<ツール名>.py` の `SYSTEM` |
| SEO の方針（ブログ） | `tools/blog.py` の `SEO_SYSTEM` |
| 検索対策の方針（note） | `tools/note_article.py` の `SEO_SYSTEM` |
| 毎回の条件（文体・文字数など） | 各ツールの `prompts.rules(...)` の中身 |

`SYSTEM` は `BASE_SYSTEM + そのツール固有の指示` という形なので、共通部分を直すと全ツールに効きます。

## 記事への写真の挿入

ブログ記事作成・note記事作成には、写真のアップロード欄があります。

1. 枠の中に写真を**ドラッグ&ドロップ**（複数まとめてOK）
   - 対応形式: **JPG / PNG / WEBP / GIF / HEIC / HEIF / BMP / TIFF**
   - iPhone や Mac の写真（HEIC）は、表示・書き出し用に自動で JPEG に変換されます
   - 縦向きの写真も EXIF の向き情報を見て正しく表示されます
2. 必要なら写真ごとに説明を書く（空欄でも、AI が画像そのものを見て判断します）
3. 記事を生成すると、本文の合う位置に `[[写真1]]` の目印が入り、**プレビューでは実際の写真が表示されます**
4. 位置を変えたいときは「🖼️ 写真の位置を調整する」で目印の行を動かすと、プレビューがすぐ切り替わります

書き出しは2種類です。

- **Markdown** — 目印が `![説明](images/ファイル名)` に置き換わります
- **ZIP** — `記事.md` と `images/` フォルダをまとめたもの。そのまま他のエディタに持っていけます

写真は**元の解像度のまま保存・書き出し**されます。AI に送るときだけ長辺1600pxに縮小するので、大きな写真を何枚入れても通信が重くなりません。

### note への貼り付け方

**写真そのものは貼り付けできません。** note のエディタは、他のページからコピーした画像を受け取らない仕様です。写真は note の編集画面にファイルをドラッグして入れる必要があります。そのため次の流れになります。

1. **「📋 note・メールに貼る用にコピー（書式つき）」** を押す
   - 見出し・太字・箇条書きが**書式のまま**クリップボードに入ります（`##` が文字のまま残りません）
   - 写真の位置は `📷 ここに写真1（説明）` という行に置き換わります
2. note の編集画面に貼り付ける
3. `📷 ここに写真1` の行に、写真をドラッグして入れ替える

写真は履歴ページからも1枚ずつダウンロードできるので、あとから作業する場合もそこから取り出せます。

## 文字数の指定

記事系のツールには、文字数の目安を数値で指定する欄があります。

| ツール | 指定できるもの | 初期値 |
| --- | --- | --- |
| ブログ記事作成 | 記事全体の文字数 | 2,500字 |
| note記事作成 | 本文の文字数 | 3,000字 |
| メール返信作成 | 本文の文字数（件名・署名を除く） | 350字 |
| SNS投稿文 | 1投稿あたりの文字数 | 媒体ごとの初期値（X なら130字） |
| 文章要約 | 「割合」と「文字数」を切り替え | 原文の約20% |
| リライト・言い換え | トグルを入れると指定可能 | 元の文章と同じくらい |

- **許容幅**（±10% / ±20% / ±30%）で厳しさを選べます。狙う範囲は入力欄の下に表示されます。
- AI は文字数ちょうどには書けないため、範囲で指示し、書き終えたあとに自己チェックさせています。
- 生成後、結果の上に **実際の文字数**が出ます。範囲内なら ✅、外れたら ⚠️ と差分を表示します。
- X は上限140字を超えないよう、上限側を自動でクリップします。
- 長い記事（5,000字以上）は途中で切れることがあります。その場合は分量を下げるか、章ごとに分けて生成してください。

## サムネイル作成について

媒体を選ぶと、比率と推奨サイズ、デザインの勘所が自動で切り替わります。

| 媒体 | 比率 | 推奨サイズ |
| --- | --- | --- |
| note の見出し画像 | 16:9 | 1280×670px |
| ブログのアイキャッチ（OGP） | 16:9 | 1200×630px |
| X（旧Twitter） | 16:9 | 1200×675px |
| Instagram（正方形 / 縦長） | 1:1 / 4:5 | 1080×1080 / 1080×1350px |
| ストーリーズ・リール・TikTok | 9:16 | 1080×1920px |
| YouTube サムネイル | 16:9 | 1280×720px |
| その他 | 自由に選択 | — |

- 「① デザイン案を考える」で構図・文字・配色の案を出してから、「② 画像を生成する」で実際の画像を作れます。
- 文字入れは **Nano Banana Pro**（`gemini-3-pro-image-preview`）のほうが日本語が崩れにくいです。それでも崩れることがあるので、生成後は必ず目で確認してください。
- 文字欄を空にすると、文字なしのビジュアルだけの画像になります（note の見出し画像はこちらも多い）。
- 生成した画像は `ai_writer/data/images/` に保存され、履歴ページからも見返せます。
- 画像生成は文章生成よりコストがかかります。枚数はまず1枚で試すのがおすすめです。

## サイドバーの設定

- **モデル** — APIキーで**実際に使えるモデルを API から取得**して並べます。迷ったら `gemini-2.5-flash`、長い記事や難しい内容は `gemini-2.5-pro`。
- **🔧 接続テスト** — 「モデルが見つかりません」と出るときは、ここの「使えるモデルを調べる」でキーが使えるモデルの一覧を確認できます。
- **創造性（temperature）** — 要約・翻訳・メールは `0.3` 前後、アイデア出しやコピーは `1.0` 以上が目安。
- **高速モード** — Flash 系で思考を省いて速度優先。短い作業向け。

## ファイル構成

```
ai_writer/
├── app.py              # 起動ファイル。ページの登録とサイドバー
├── core/
│   ├── config.py       # APIキー・モデルなどの設定
│   ├── gemini.py       # Gemini API 呼び出し（ストリーミング／エラー処理）
│   ├── prompts.py      # プロンプト組み立ての共通部品
│   ├── history.py      # 履歴の保存・読み出し
│   └── ui.py           # 共通UI（サイドバー・生成結果パネル）
├── tools/              # ツール1つにつき1ファイル
└── data/
    ├── history.json    # 履歴（自動生成・Git管理外）
    └── images/         # 生成したサムネイル（自動生成・Git管理外）
```

### ツールを追加したいとき

1. `ai_writer/tools/` に新しいファイルを作り、`render()` 関数を書く
2. `app.py` の `TOOLS` に1行足す

`render()` の中身は、入力欄を並べて `ui.render_output(...)` にプロンプトを渡すだけです。
既存のファイル（例: `tools/rewrite.py`）をコピーして書き換えるのが早いです。

## 履歴の削除

履歴ページでは、各行の右にある **🗑️ をクリックするだけで1件ずつ削除**できます（開く必要はありません）。

- 削除すると上部に「元に戻す」が出ます。押し間違えてもすぐ戻せます
- **記事に入れた写真も一緒に保存される**ので、履歴でも写真つきで見返せます（1枚ずつダウンロード / ZIP 書き出しも可）
- 記事を開いた中にも削除ボタンがあります
- サムネイルの履歴を消すと画像ファイルが残ります。ページ下部の「どの履歴にも紐づいていない画像」からまとめて掃除できます
- 全件削除は下部の「🧹 履歴をすべて削除」から（こちらは元に戻せません）

## 注意

- エラーが出たときは、メッセージの末尾に API が返した生の内容が「詳細:」として付きます。原因の切り分けに使ってください。
- `ai_writer/` の中のファイルを編集したあと `KeyError: 'ai_writer.core'` が出たら、ターミナルで `Ctrl + C` して起動し直してください（Streamlit の自動リロードがパッケージの再読み込みに失敗したときに起きます）。
- 出力は AI が書いた下書きです。**事実・固有名詞・数値は必ず自分で確認**してから使ってください。
- 入力した文章は Gemini API に送信されます。機密情報の扱いには注意してください。
- 履歴は `ai_writer/data/history.json` に平文で保存されます（Git 管理外）。
- 生成した画像に含まれる文字は AI が描いたものです。**誤字がないか必ず確認**してから公開してください。
